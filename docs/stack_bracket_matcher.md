# Bracket matching with stack

**更好的写法是：采用“单一出口（Single Exit）”模式。** 用一个标志变量 `valid` 记录状态，一旦发现失效，就 `break` 跳出循环，最后**统一**在函数末尾释放内存并返回结果。

这样做的好处是：**成功和失败路径泾渭分明**，内存管理只写一次，绝不出错。

请看下面重构后的代码，注释里明确标出了 **“失效路径”** 和 **“成功路径””**：

```c
#include <stdbool.h>
#include <stdlib.h>
#include <string.h>
#include <stdio.h>

bool isValid(char *s) {
    int len = strlen(s);
    
    // 【边界成功】空字符串直接视为有效
    if (len == 0) {
        return true;
    }

    // 1. 分配栈空间
    char *stack = (char*)malloc(len * sizeof(char));
    if (stack == NULL) {
        return false; // 内存分配失败（系统级错误）
    }

    int top = -1;           // 栈顶指针
    bool valid = true;      // 【核心标志】默认为有效，只有遇到明确错误才改为 false

    // 2. 遍历字符串
    for (int i = 0; i < len; i++) {
        char c = s[i];

        // --- 分支一：左括号，入栈 ---
        if (c == '(' || c == '[' || c == '{') {
            stack[++top] = c;
            continue; // 处理下一个字符
        }

        // --- 分支二：右括号，开始匹配检查 ---
        // 【失效条件 1】栈为空 => 没有左括号可以匹配
        if (top == -1) {
            valid = false;
            break; // 立即终止遍历
        }

        // 取出栈顶左括号
        char topChar = stack[top];

        // 【失效条件 2】栈顶括号与当前右括号不成对
        if ((c == ')' && topChar != '(') ||
            (c == ']' && topChar != '[') ||
            (c == '}' && topChar != '{')) {
            valid = false;
            break; // 立即终止遍历
        }

        // --- 匹配成功：弹出栈顶 ---
        top--;
    }

    // 3. 【最终判定】遍历结束后，如果 valid 为 true 但栈不为空，说明有多余左括号，依然失效
    if (valid && top != -1) {
        valid = false;
    }

    // 4. 【单一出口】统一释放内存，统一返回结果
    free(stack);
    return valid;
}

// 主函数（用于测试）
int main(int argc, char *argv[]) {
    if (argc != 2) {
        printf("用法: %s \"括号字符串\"\n", argv[0]);
        return 1;
    }

    printf("%s\n", isValid(argv[1]) ? "有效" : "无效");
    return 0;
}
```

---

### 为什么这样写“分得明确”？

1. **失效场景高度集中**  
   代码中明确列出了 **仅有的 3 种失效情况**：
   - 栈空了，却来了右括号（`")"`）
   - 栈顶不匹配（`"(]"`）
   - 遍历完了，栈里还剩东西（`"((()"`）  
   这三种情况一旦触发，`valid` 立即变 `false`，然后 `break` 跳出。

2. **成功场景只有一条路**  
   只有**全程没触发 break**，且遍历结束后 `top == -1`，`valid` 才保持 `true`。

3. **内存释放只有一处**  
   无论成功还是失败，`free(stack)` 都只写在最后，绝无遗漏风险，代码极度整洁。

这种写法在大型工程项目中非常推荐，因为**修改和维护时，你不需要在十几个 `return` 里找遗漏的 `free`**，逻辑一目了然。

# 从定义出发，来解决这个问题

太棒了！你已经触及了计算机科学最底层的“形式语言”基石。现在，我们就**彻底抛弃“栈”、“消消乐”、“先删外层”这些名词**，把自己变成一个**只会机械执行集合论定义的文字处理机**。

我们从**最最最笨**的“暴力穷举生成法”开始，一步步推导出算法。全程不跳跃，只用简单的逻辑推理。

---

### 第0步：拿到“集合论定义”这把尺子

我们先把这个定义写在黑板上，这就是我们的**唯一真理**（也是唯一能用的规则）：

- **公理**：空字符串 `ε` 是有效的。
- **规则1（并列）**：如果 `A` 有效，`B` 有效，那么把 `A` 和 `B` 拼在一起（`AB`）也有效。
- **规则2（包裹）**：如果 `A` 有效，那么 `(A)`、`[A]`、`{A}` 也有效。

**定义：** 一个字符串有效，**当且仅当**它能通过上面的规则有限次生成出来。

---

### 第一步：最笨的“生成验证法”——尝试所有生成路径

现在，给你一个字符串 `s = "()()"`，我想验证它是否有效。

作为最笨的机器，我不知道任何技巧。我只能**逆向思考**：
> “既然有效字符串都是由规则生成的，那如果 `s` 有效，它最后一次被生成时，**一定用了规则1（并列）或规则2（包裹）**。”

于是，我的验证方法就是**暴力回溯**：

1. **尝试规则2（包裹）**：检查 `s` 是不是 `(A)` 的形式？
   - `s = "()()"`，第一个字符是 `(`，最后一个字符是 `)`，看似包裹。去掉外壳得到 `A = ")("`。
   - 检查 `A = ")("` 是否有效？显然无效（以右括号开头）。所以这条路不通。

2. **尝试规则1（并列）**：检查 `s` 能不能拆成 `AB`，其中 `A` 和 `B` 都有效？
   - 尝试在位置 1 拆分：`A = "("`, `B = ")()"`。`A` 无效，失败。
   - 尝试在位置 2 拆分：`A = "()"`, `B = "()"`。检查 `A`（有效），检查 `B`（有效）。**成功了！**
   - 得出结论：`"()()"` 有效。

**这个“暴力穷举拆分”的算法，是 100% 正确的**，因为它直接照搬了定义。但它的时间复杂度是指数级的（要尝试所有拆分位置，还要递归检查子串）。

---

### 第二步：在暴力拆解中，发现“并列”的隐藏模式

让我们盯着上面“暴力拆分”的过程，尤其是成功的那一步（在位置 2 拆分）。

为了验证 `A = "()"` 是否有效，机器做了什么？
- 它发现 `"()"` 不是并列，而是包裹 `(ε)`，所以有效。

当机器验证完 `A` 后，**机器内部的“状态”是什么？**
- 它发现 A 有效，意味着 A 里的左右括号**完全抵消了**。

现在，我们换个角度，**不是“切开来检查”，而是“从左到右扫描”**。

当我们从左到右扫描 `"()()"` 时：
1. 读到 `(`，我们不知道它属于 A 还是 B，但我们知道**它必须有一个 `)` 来配对**。为了记住这个 `(`，我们在脑子里记下：“当前有一个未配对的 `(`”。
2. 读到 `)`，发现它能配对上最近的那个 `(`。配对成功！脑子里把那个 `(` 划掉。
   - **此时，脑子里没有任何未配对的括号了。这意味着什么？** 意味着我们刚刚完整地识别出了一个有效的 `A`（即第一个 `()`）。
3. 继续读到 `(`，脑子里记下：“又有一个未配对的 `(`”。
4. 读到 `)`，配对成功，划掉。

**关键发现来了：** 在暴力拆分中，我们需要“人为地”在 A 和 B 之间切一刀（位置 2）。但在从左到右扫描中，**当 A 被完整识别时（即栈为空时），这一刀就“自动”划在这里了**。我们根本不需要去尝试所有拆分位置，因为“栈为空”这个事件，天然就是 `AB` 并列的分界线！

---

### 第三步：暴力拆解中的“包裹”模式，如何被扫描处理？

再看 `"{()()}"`。

暴力拆解中，我们先用规则2，剥掉外层 `{}`，得到 `"()()"`，然后继续递归。

在从左到右扫描中：
1. 读到 `{`，记下：“有一个未配对的 `{`”。
2. 读到 `(`，记下：“有一个未配对的 `(`”。
3. 读到 `)`，配对，划掉 `(`。
4. 读到 `(`，记下。
5. 读到 `)`，配对，划掉。
6. 读到 `}`，**此时脑子里最后记着的是什么？是 `{`**。配对，划掉。

**关键发现：** 在暴力递归中，“剥掉外层”是**后发生**的（先验证内层，再验证外层）。在从左到右扫描中，外层 `{` 被**先记下**，却**最后被划掉**。这个“先记下，后划掉”的顺序，完美模拟了递归中“先进入内层，再返回外层”的调用栈顺序。

---

### 第四步：把“脑子里的记事本”变成代码（最笨的数据结构）

现在，我们来设计这个“脑子里的记事本”。

需求很简单：
1. 遇到左括号，我要记下来（**写**上去）。
2. 遇到右括号，我要看最近记下的那个左括号（**读**最后写的那个）。
3. 如果配对，我就把最近记下的那个擦掉（**删**最后写的那个）。

请问：**如果让你用一张纸和一支笔，手动模拟这个“读最后写的、删最后写的”，你会怎么操作？**

答案不言自明：**把纸竖起来，像叠盘子一样，从下往上写。**
- 写（入栈）：永远写在最上面。
- 读（查看）：永远只看最上面。
- 删（出栈）：永远撕掉最上面那张。

这个操作，在计算机里就叫**数组 + 顶部指针（top）**。

---

### 第五步：推导出最终的“呆板”代码（完全对应定义）

基于上面的推导，我们写出的代码逻辑，**根本就不是“我想出来的”，而是“被定义逼出来的”**：

```c
// 1. 对应公理：空字符串有效。但我们在循环中处理，最后检查栈空。
// 2. 对应规则2（包裹）和规则1（并列）：
//    从左到右扫描，用栈记录“正在等待配对的左括号”。
//    遇到右括号，必须匹配栈顶（这就是包裹规则的逆向操作）。
//    如果栈在中间空了，说明一个并列单元结束了，继续扫下一个。
//    如果扫描完栈为空，说明整体由若干并列单元组成，有效。

int top = -1;
for (int i = 0; i < len; i++) {
    if (s[i] == '(' || s[i] == '[' || s[i] == '{') {
        stack[++top] = s[i];  // 遇到了包裹的左边界，记下来
    } else {
        // 遇到了右边界，必须找最近的那个左边界（栈顶）
        if (top == -1) return false; // 栈空，说明没有左边界可以配，违反规则
        if (不匹配) return false;     // 配错了，违反包裹规则
        top--; // 配对了，把这个左边界划掉，相当于递归返回了一层
    }
}
return top == -1; // 对应公理：空字符串有效，且并列单元全部处理完
```

### 最终总结：集合论 -> 算法的推导链条

现在，你可以把整个“跳跃”彻底消灭在摇篮里了：

| 集合论定义 | 最笨的暴力验证（逆向拆解） | 从左到右扫描时的等价操作 | 最终代码表现 |
| :--- | :--- | :--- | :--- |
| **公理**：空有效 | 递归终点 | 扫描结束，栈必须为空 | `return top == -1` |
| **规则2（包裹）**：`(A)` | 剥掉最外层，检查 `A` | 左括号入栈，右括号时查看栈顶并弹出 | `push` 和 `pop` |
| **规则1（并列）**：`AB` | 尝试所有位置拆分 `A` 和 `B` | A 处理完后栈为空，B 接着处理（无需额外标记） | 循环继续，不做特殊处理 |

**结论：** 
你不是“想到了”栈，你是**被迫使用**栈。因为定义中的“包裹”规则，天然要求“后遇到的外层括号，必须等待内层处理完才能闭合”，这种“后进先出”的匹配顺序，只允许用“栈”这种数据结构来完美映射。其他数据结构（如队列）无法模拟“递归返回”时的内存回溯。

这套推导方法，就是编译原理中“递归下降解析器”转化为“状态机/栈式解析器”的标准过程。你现在完全靠自己走通了这条路！
